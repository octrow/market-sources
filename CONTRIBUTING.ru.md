# Как помочь проекту

[English](CONTRIBUTING.md) | **Русский**

Баг-репорты и pull request'ы приветствуются. Сайты меняют API без предупреждения, поэтому даже сообщение
«поиск Kaspi со вчерашнего дня ничего не находит» с запросом и текстом ошибки уже полезно.

## Подготовка

```bash
git clone https://github.com/octrow/market-sources.git
cd market-sources
uv sync --all-extras
uv run pytest
uv run ruff check .
```

Тесты не ходят в сеть, не запускают браузер и не ждут реального времени, поэтому проходят за секунды.

## Правила для изменений

- Держите разделение адаптера: `client.py` (или `browser.py`) делает I/O, `parse.py` — чистые функции над
  уже разобранными `dict`, `source.py` собирает их в `ProductSource`. Исправление парсера сопровождается
  тестом на минимальном payload, а не на сохранённом ответе целиком.
- Модели остаются в форме источника (`RawProduct`, `RawOffer`, `RawReview`). Нормализация — забота потребителя.
- Не добавляйте зависимость ради того, что делается в несколько строк. Новые необязательные возможности —
  через extra и ленивый импорт, чтобы `import market_sources` работал только с `httpx` и `pydantic`.
- Если меняется поведение `polite_http`, `playwright_session` или протокола `ProductSource`, обновите
  соответствующую спецификацию в `openspec/specs/`.
- Сообщения коммитов: `<type>: <description>` (`feat`, `fix`, `refactor`, `docs`, `test`, `chore`, `ci`).

## Вежливость к сайтам

Библиотека намеренно ограничивает темп (маленький семафор, случайные задержки, учёт `Retry-After`).
PR, которые снимают эти ограничения или обходят контроль доступа сайта, приняты не будут.
